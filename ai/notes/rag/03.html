30 SECONDS / 30 秒看懂

这一关只解决一件事：检索前先用元数据过滤，再做向量相似度。

  • 入库保存文本、embedding 和元数据
  • 查询先按 is_active/版本/部门过滤
  • 再做向量相似度取 Top-K

查询：where 过滤 → 余弦 → Top-K

为什么过滤要发生在相似度计算之前？

SOURCE READING / 来源精读

SemanticSeek 用 Embedding 把查询和文档转成向量，再用余弦相似度计算相关性，并按 Top-K 返回最相关文档。

逐点读懂

  1. 语义检索不是关键词匹配，而是比较查询与文档的向量表示。
  2. 来源使用 Ollama 的 nomic-embed-text 模型生成 embedding。
  3. 检索结果按相似度排序，返回 Top-K 文档。
  4. 语义检索适合自然语言问法，但仍需要文档侧的准备和索引。

怎么对应本关练习

本关的入库结构、元数据过滤和查询逻辑，是在来源的语义检索链路上增加工程约束。

例子在哪

来源 README 用酒店洗衣服务的自然语言查询展示 Top-K 结果和相似度分数。

核心原理

在 StepByStep-RAG 的第二模块 SemanticSeek 与 AI Infra Engineer Learning (Mod 110) 中,传 统的 Ctrl+F 或关键词搜索在面对“用戶问:电脑连不上公司内网怎么办”而知识库原文写的是“企业 VPN 客 戶端认证失败排查指南”时,会因为字面词汇零重合而完全搜不到结果。语义检索(Semantic Search)通过 将文本块编码为稠密向量并存入向量数据库(如 Chroma、Qdrant、Weaviate),同时绑定结构化元数据过滤 条件(Metadata Filtering,如 department == "IT" 且 year >= 2025),实现“既懂弦外之音、又守精确边界” 的高效检索。
