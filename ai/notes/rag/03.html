语义检索引擎构建

在 StepByStep-RAG 的第二模块 SemanticSeek 与 AI Infra Engineer Learning (Mod 110) 中，传

约 3 分钟·免费阅读·整理自 StepByStep-RAG / GraphRAG / RAG 评估实践·直接做题 ↓

核心原理

在 StepByStep-RAG 的第二模块 SemanticSeek 与 AI Infra Engineer Learning (Mod 110) 中，传统的 Ctrl+F 或关键词搜索在面对“用户问：电脑连不上公司内网怎么办”而知识库原文写的是“企业 VPN 客户端认证失败排查指南”时，会因为字面词汇零重合而完全搜不到结果。语义检索(Semantic Search)通过将文本块编码为稠密向量并存入向量数据库（如 Chroma、Qdrant、Weaviate），同时绑定结构化元数据过滤条件（Metadata Filtering,如 department == "IT" 且 year >= 2025），实现“既懂弦外之音、又守精确边界”的高效检索。

第 3 关实操练习题：构建带元数据预过滤的本地 Chroma/Qdrant 语义检索管道

任务背景

知识库里同时存有 2023 年（已废止）和 2026 年（现行有效）的差旅报销标准，单纯靠向量相似度检索经常把 2023 年的旧住宿标准排在第一名。

通关硬性要求（满分 12.5 分）

1. 设计文档入库(Upsert)时的三维结构：id、document_text、embedding 与 metadata（含版本号、生效状态 is_active、适用部门）（4.5 分）；

2. 编写检索查询逻辑，在计算向量相似度前先通过 where={"is_active": True} 过滤掉历史废止文档（5分）；

3. 说明为什么查询向量(Query Embedding)与文档入库向量必须使用完全相同的 Embedding 模型与归一化方式（3 分）。

# 1. 结构化入库结构(绑定版本与生效状态元数据)
collection.upsert(
ids=["policy_2026_chunk_01", "policy_2023_chunk_01"],
embeddings=[embed_model.encode(text_2026), embed_model.encode(text_2023)],
documents=[text_2026, text_2023],
metadatas=[
{"doc_name": "差旅制度", "effective_year": 2026, "is_active": True, "dept": "ALL"},
{"doc_name": "差旅制度", "effective_year": 2023, "is_active": False, "dept": "ALL"}
]
)
# 2. 检索时强制前置过滤 is_active == True,彻底屏蔽废止旧制度
results = collection.query(
query_embeddings=[embed_model.encode("一线城市出差住宿报销上限是多少?")],
n_results=3,
where={"$and": [{"is_active": {"$eq": True}}, {"effective_year": {"$gte": 2026}}]}
)

得分要点拆解

完整定义四维入库结构与 `is_active` 元数据（4.5 分）；使用 `where` 过滤器在向量比对前剔除失效旧文档（5 分）；说明不同 Embedding 模型向量空间正交不可混用、必须保持同一模型与归一化标准（3 分）。
