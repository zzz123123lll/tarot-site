核心原理

传统向量切片 RAG 擅长回答“局部细节查找题”,但在面对“跨全库全局归纳题”（例如：“综合这500 份客户投诉工单，今年最核心的三大系统性质量问题及其关联供应商分别是什么？”）时往往彻底失效，因为 Top-5 局部片段根本无法代表全部 500 份文档的全貌！微软开源的 Microsoft GraphRAG 提出了革命性解法：在索引阶段利用大模型从文本中抽取实体(Entities)与关系(Relationships)构建知识图谱，通过Leiden 社区发现算法对紧密关联的实体群落生成多层级的社区摘要(Community Summaries)。查询时：

局部细节问题走 Local Search（实体邻域遍历 + 原文块），宏观全局问题走 Global Search（Map-Reduce汇总各社区摘要）。

// 2. 查询路由判定规则（Query Router）
- 路由至 Local Search（向量 + 实体一跳邻域）：针对特定实体或具体数值的微观问题，如“麒麟电池的体积利用率是多少？”
- 路由至 GraphRAG Global Search（社区摘要 Map-Reduce）：针对跨多篇研报的宏观趋势、主题归纳与全集统计问题，如“总结这 200 份研报中提到的固态电池量产三大共性技术瓶颈”。
- 成本优化方案：仅对核心深度研报与长周期规范文档启用 LLM 图谱抽取，日常短资讯仍采用轻量向量索引。

得分要点拆解

规范定义产业链实体与三元组关系 Schema（5 分）；清晰区分微观细节查询(Local Search)与跨全库全局归纳查询(Global Search)（4.5 分）；给出混合索引控本策略（3 分）。
