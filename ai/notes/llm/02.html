SOURCE READING / 来源精读

来源引用：在微调中，数据质量永远比堆砌超参数重要十倍；新手最常踩的两个坑是对话模板错配和 EOS 结束符丢失。

逐点读懂

  1. 基座/指令模型遵循严格特殊控制符格式，如 ChatML 与 Llama 3。
  2. 漏掉 assistant 末尾 eos_token，模型推理时不知道何时停止。
  3. 未只对 Assistant 回复计算 Loss 会让模型浪费算力背诵 User 问题。
  4. 标准做法：三角色 JSON、ChatML 展开、Completion-only Loss Masking。

怎么对应本关练习

读本关时先检查数据格式，再看训练参数；格式错，参数再对也没用。

核心原理

正如 mlabonne/llm-course 第 3‒4 章 所言:“在微调中,数据质量永远比堆砌超参数重要十倍 (Always prioritize data quality over parameter optimization)。”新手做微调最常踩的两个致命大坑: 对话模板(Chat Template)错配与结束符(EOS Token)丢失:基座模型与指令模型遵循严格的特殊控 制符格式(如 ChatML 的 <|im_start|>user...<|im_end|> 或 Llama 3 的 <|start_header_id|>... <|eot_id|>)。如果在拼接训练样本时漏掉了助手回答末尾的 eos_token,微调后的模型在推理时永远不知 道何时停下来,会一直自言自语直到填满最大长度! 未只对 Assistant 回复计算 Loss(Completion-only Loss Masking):如果把用戶提问(Instruction) 也算进交叉熵损失,模型会浪费算力去背诵用戶的问题,甚至学会模仿用戶的语气反问用戶。
