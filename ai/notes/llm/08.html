核心原理

在 AI Infra Engineer Learning (Mod 110) 与 mlabonne/llm-course 的 The LLM Engineer 篇章 中,很多初学者用 Hugging Face 原生的 model.generate() 套个 FastAPI 就敢上线,结果 5 个用戶同时访问就 把服务器卡死!生产环境必须使用 vLLM 或 TGI 等专用推理引擎。vLLM 之所以能将吞吐量提升 10‒20 倍,核 心在于三大黑科技: PagedAttention(分页注意力机制):借鉴操作系统虚拟内存分页思想,将原本必须连续分配、浪费高达 60% 的 KV Cache 显存拆分为非连续的固定大小物理块(Blocks),将显存利用率推升至 95% 以上。 Continuous Batching(连续批处理 / Iteration-level Scheduling):不再等一个 Batch 里最慢的长句子 生成完才放新请求进来,只要批次里有任意一条请求生成结束(遇到 EOS),下一个排队请求立刻在下一 个 Token 迭代周期无缝插队补位。 Prefix Caching(自动前缀缓存)与 Multi-LoRA Serving:自动缓存所有请求共享的长 System Prompt 或 Few-Shot 示例的 KV Cache,无需重复计算首字延迟(TTFT);且支持在一个基座模型实例上同时挂载 数十个不同业务的轻量 LoRA 适配器动态切换。

vLLM 生产级多 LoRA 动态部署命令与压测基线

# 1. vLLM 生产级启动命令(开启 AWQ 量化、前缀缓存与多 LoRA 动态挂载)

vllm serve Qwen/Qwen2.5-14B-Instruct-AWQ \

--quantization awq \

--max-model-len 8192 \

--gpu-memory-utilization 0.90 \

--enable-prefix-caching \

--enable-lora \

--max-loras 4 \

--max-lora-rank 32 \

--lora-modules legal-lora=./adapters/legal_sft_v1 marketing-lora=./adapters/mkt_sft_v2 \

--port 8000

# 2. 客戶端通过 OpenAI SDK 动态指定调用“法务审查 LoRA”

from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")

resp = client.chat.completions.create(

model="legal-lora", # 直接传入 --lora-modules 中注册的适配器别名即可零停机切换!

messages=[{"role": "user", "content": "请审查以下违约金条款是否合法..."}],

temperature=0.0

)

生产压测三大核心指标定义:1 TTFT(Time To First Token,首字延迟):从发送请求到收到第一个输出

Token 的耗时,反映 Prompt 预填充(Prefill)与排队速度,交互式对话要求 < 500ms(开启 --enable-

prefix-caching 可大幅降低 TTFT);2 TPOT / ITL(Time Per Output Token,单字生成间隔):解码阶段每

生 成 下 一 个 Token 的 平 均 耗 时 , 决 定 打 字 机 流 畅 度 , 人 类 阅 读 舒 适 线 要 求 < 40ms/token ( 即 > 25

tokens/s);3 System Throughput(系统总吞吐量):在高并发下每秒为所有用戶生成的总 Token 数,衡量

单卡商业承载力与单位 Token 成本。
