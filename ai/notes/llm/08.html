核心原理

在 AI Infra Engineer Learning (Mod 110) 与 mlabonne/llm-course 的 The LLM Engineer 篇章中,很多初学者用 Hugging Face 原生的 model.generate() 套个 FastAPI 就敢上线,结果 5 个用戶同时访问就把服务器卡死!

生产环境必须使用 vLLM 或 TGI 等专用推理引擎。

vLLM 之所以能将吞吐量提升 10‒20 倍,核心在于三大黑科技: PagedAttention(分页注意力机制):借鉴操作系统虚拟内存分页思想,将原本必须连续分配、浪费高达 60% 的 KV Cache 显存拆分为非连续的固定大小物理块(Blocks),将显存利用率推升至 95% 以上。

Continuous Batching(连续批处理 / Iteration-level Scheduling):不再等一个 Batch 里最慢的长句子生成完才放新请求进来,只要批次里有任意一条请求生成结束(遇到 EOS),下一个排队请求立刻在下一个 Token 迭代周期无缝插队补位。

Prefix Caching(自动前缀缓存)与 Multi-LoRA Serving:自动缓存所有请求共享的长 System Prompt 或 Few-Shot 示例的 KV Cache,无需重复计算首字延迟(TTFT);且支持在一个基座模型实例上同时挂载数十个不同业务的轻量 LoRA 适配器动态切换。
