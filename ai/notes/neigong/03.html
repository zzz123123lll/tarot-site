30 SECONDS / 30 秒看懂

这一册只解决一件事：深度推理模型为什么“先想再答”，以及为什么旧的分步提示词不再适用。

  • 不写草稿时，模型只有一次前向传播的算力
  • CoT 用输出长度换推理深度，是 Test-Time Compute

内功03:深度推理模型(Reasoning Models)与思维链 机制——从 CoT、R1 到 V4.1 统一混合推理 搞懂 AI 近两年最大的范式革命:Test-Time Compute 测试时计算扩展、GRPO 强化学习顿悟涌现,以及为什 么对推理模型不能再用老套提示词 核 心 知 识 参 考 : DeepSeek V4/V4.1 API Docs 、 DeepSeek-R1 (GRPO) 、 Claude 5.5 Adaptive Thinking 与 OpenAI GPT-6 Interleaved Thinking

一、顿悟时刻:哦,原来“思维链”和“深度推理模型”背后是这个数学原理!

在使用大模型时,你一定注意到了一个分水岭式的变化:现在的 ChatGPT(GPT-6 Sol / Luna / Astra 与 GPT-

6.1 Sol)、Claude(Claude Fable 5.1 / Opus 5.5 / Sonnet 5.5 Adaptive Thinking)、Google(Gemini 4 Argon

/ 3.5 Pro)、阿里 Qwen3.8(2.4T-A95B / 27B)以及 DeepSeek-V4.1-Flash-1017 / DeepSeek-V4-Pro(源自 DeepSeek-R1),在回答复杂问题前都会先弹出一个折叠框“正在深度思考(Thinking...)”,自己跟自己辩论 几十秒后再给出答案。为什么多出这个思考框,模型的数学、编程和复杂逻辑能力就会发生质的⻜跃?我们先 用两个直击本质的原理帮你彻底顿悟。 真相一:为什么模型“不写草稿”就做不对复杂题?揭秘 Transformer 的“单步算力天花板” 假设一个大模型内部有 80 层神经网络。当你问它一道需要转 5 个弯的逻辑推理题,如果要求它第一个字就直接 吐出最终答案(“选 C”),那么模型从读完题目到算出“C”,最多只能经过这 80 层网络的一次前向传播(1 Forward Pass)!如果这道题的计算复杂度超过了 80 层矩阵乘法能承载的上限,模型就算再聪明也算不过 来,只能靠直觉蒙一个答案。 而当我们允许模型在给出最终答案前,先输出 500 个字的中间推演步骤(即 Chain-of-Thought, CoT 思维链) 时,神奇的事情发生了:模型每吐出 1 个中间步骤的字,就跑了 1 次 80 层网络;吐出 500 个字,就足足跑了 500 次 80 层网络!而且前面算出来的每一个中间结论,都作为可见文字留在了上下文窗口里,供下一步直接读 取。把思考过程变成文字吐出来,本质上就是突破单步算力限制、用输出长度换取算力深度(即 Test-Time Compute Scaling,测试时计算扩展)! 真相二:“手写提示词让模型一步步想(Prompted CoT)” vs “原生推理模型(从 DeepSeek-R1 到 V4.1 / GPT-6 / Claude 5.5)”有什么本质区别? 在 2024 年以前,人们想让模型列草稿,必须在提示词里手把手教它:“请你分三步思考:第一步先算A,第二步再算 B......”(这叫外置提示词思维链,模型只是在机械模仿人类写的步骤格式,一旦第一步算错,它就会将错就错一 路错到底)。 而以 DeepSeek-R1 与 OpenAI o 系列开创、并演进至今日 DeepSeek-V4.1 / GPT-6 / Claude 5.5 的原生推理模 型(Native Reasoning Models),是在后训练阶段通过大规模强化学习(Reinforcement Learning,如 DeepSeek 提出的 GRPO 群组相对策略优化算法)训出来的:研究人员只给模型海量高难度数学、代码和逻辑 题,不规定它中间怎么想,只根据最终答案对不对给奖励分!在数万次强化博弈中,模型自己进化出了四种人 类从未手把手教过它的元认知本能:

1. 自我验算与回溯(Self-Verification & Backtracking):你会在它的思考框里看到它突然写一句“Wait(等

等),如果按刚才的假设代入第二个条件会出现矛盾,说明我刚才走错路了,让我推翻重来......”

2. 多路径假设探路(Hypothesis Exploration):一条路走不通时,主动尝试第二种解法。

3. 问题拆解与边界检查(Edge-Case Checking):写完代码后自己在脑海里拿极端值(如 n = 0 或负数)跑一

遍干测(Dry Run)。 对比维度 快思考通用模型(System 1) 如低思考档位(effort=low)下的 DeepSeek-V4.1-Flash / Qwen3.8-Flash- Next / Claude Haiku 5.5 慢思考深度推理模型(System 2) 如高思考档位(high/max)下的 DeepSeek-V4-Pro / V4.1-Flash / Qwen3.8-2.4T / GPT-6 Sol / Claude Fable

5.1 & Opus 5.5

核心运作机制 接收到指令后立即开始生成最终回复,反应 极快(首字延迟 < 1秒),依赖直觉模式匹 配。 先在隐藏或可见的 <think>...</think> 空间 内消耗数百至数万个推理 Token 进行多轮假 设、验算与纠错,再输出最终答案。 最佳适用任务 日常翻译、文本润色、已知知识的快速问 答、固定格式的 JSON 提取、低延迟实时对 话。 复杂算法与架构设计、数学/物理推演、多约 束条件冲突排期、隐蔽逻辑漏洞排查、深度 综合研究方案。 提示词设计铁律 (极其关键!) 需要“保姆式结构化指导”:最好给出分步执 行顺序(Step 1, Step 2)与 Few-Shot 样 本。 必须采用“极简目标 + 验收边界”法! 严禁 硬塞繁琐的人为思考步骤或过多 Few-Shot (会干扰它原生的强化学习探索路径)!

二、核心心法深讲:如何正确驾驭现代深度推理模型(DeepSeek-V4.1 / GPT-6 /

Claude 5.5 Adaptive Thinking)?

1. 为什么对推理模型用“传统老套路提示词”反而会让它变笨?

很多学习者习惯了以前给 GPT-3.5 / GPT-4 写几百字的“专家角色咒语 + 请严格按以下五步思考 + 三个少样本例 子”,结果把这套提示词原封不动发给 DeepSeek-V4-Pro、GPT-6 Sol 或 Claude Opus 5.5,发现回答质量反而 下降了!在 DeepSeek-R1 官方技术报告与 OpenAI 推理模型指南中,明确指出了驾驭推理模型的“三要三不 要”黄金法则: 法则一:不要替它规定“怎么想(How to think)”,要极其清晰地定义“终极目标与硬性约束(What & Constraints)”——推理模型自己内部已经有一套经过强化学习千锤百炼的思考流。如果你强行规定它“第 一步必须先想A、第二步想B”,就像逼一位围棋九段高手必须按初学者口诀下棋一样,会直接锁死它的回溯 与自我纠错能力! 法则二:不要在推理模型里塞过多 Few-Shot 样本,尽量用 Zero-Shot 直接陈清边界——研究表明,过多 的人工示范样本会让推理模型过度拟合样本的表面格式,反而抑制了它在 `` 阶段做深层逻辑推演的长度。 法则三:不要再用“Let's think step by step(请一步步思考)”这类过时咒语——原生推理模型每次回答 都会自动进入 `` 阶段,再写这句话纯属画蛇添足。你真正需要写清的是【全部已知事实数据】、【绝对不可 违反的硬性限制条件】以及【最终交付物的验收标准】。

2. 正反对比:面向传统模型 vs 面向深度推理模型的提示词重构

过时写法(强行干预思考过程,束缚推理模型手脚): 你是一位拥有20年经验的顶级运筹学大师。请一步一步思考(Let's think step by step): 第一步,请先按距离远近给所有城市排序; 第二步,请用贪心算法每次选择最近的城市; 第三步,请输出路线。 (问题:贪心算法在旅行商问题上往往不是全局最优解!你强行规定它第二步用贪心算法,直接害得推理模型放弃了 搜索真正最优解的机会!) 现代推理模型写法(极简目标 + 完整约束 + 验收标准):

【任务目标】请为以下 6 个配送站点规划一条总耗时最短的闭环配送路线(从站点 A 出发,遍历所有站点后返回

A)。

【已知数据与约束条件】

1. 各站点间的通行耗时矩阵如下:(附上矩阵数据);

2. 硬性时间窗约束:站点 C 必须在出发后 90 分钟内送达;站点 E 与站点 F 不能连续相邻访问。

【输出验收要求】

请给出最终最优路线序列、每个站点的累计到达时间,并证明该路线满足全部两项硬性约束且总耗时最短。

3. 高阶工程范式:“慢思考军师(Planner)+ 快思考工兵(Executor)”双模混合架构

既然推理模型这么强,为什么我们不把所有任务都交给它?因为推理模型有两个物理代价:一是慢(动辄思考 20〜60 秒),二是贵(思考过程产生的几千个内部 Token 全部要计费)。因此,2026 年最成熟的工程实践是 “双模型解耦协同(Model Routing)”:

1. 第一棒(调用 DeepSeek-V4-Pro [max] / Claude Fable 5.1 / Opus 5.5 / GPT-6 Sol):只调用 1 次,负责

啃最硬的⻣头——阅读复杂需求、排查逻辑冲突、输出一份结构严密的《技术架构与分步实施蓝图》;

2. 第二棒(调用 DeepSeek-V4.1-Flash-1017 [low] / Qwen3.8-Flash-Next / Claude Haiku 5.5 等高速模

型):拿着第一棒生成的蓝图,以 10 倍的速度、1/10 的成本并发执行具体的文本润色、数据格式转换或批量 代码填充!

三、动手实验(Hands-on Lab):解剖推理模型的“顿悟与回溯轨迹”

实验 1:观察推理模型在逻辑陷阱题中的“自我推翻(Backtracking)”过程 实验准备:打开 DeepSeek(开启“深度思考 R1”)、Claude(开启 Extended Thinking)或 ChatGPT(选 择 Thinking 模型)。 输入以下包含隐蔽反直觉陷阱的题目: 一个房间里有 3 盏灯,房间外走廊上有对应的 3 个开关(A、B、C),在走廊上看不见房间里的灯光。你现在在走廊 上,可以任意拨动开关,但你只有【唯一一次】推门进入房间观察的机会。请问你如何 100% 确定哪一个开关控制哪 一盏灯?(注意:这 3 盏灯全部是最新款的低温 LED 灯,通电 1 小时外壳也不会发热,温度与环境完全一致;房 间内也没有镜子或摄像头。) 观察重点:点开模型的“思考过程(Thinking Process)”折叠框!你会亲眼看到模型一开始习惯性地想用 经典的“先开 10 分钟摸灯泡温度”老套路,随后突然意识到题目里写着“低温 LED 灯不发热”,紧接着在思 考框里自我否定并开始探索新解法(如利用 LED 驱动电容断电后的微弱余辉放电、或拆卸开关面板检查线路 通断等物理边界条件)。这种“发现老套路失效 → 主动推翻 → 寻找新维度”的过程,正是强化学习推理模 型最迷人的内核!

参考答案与解析

1. 第 1 题解析:模型的参数量并没有变多,改变的是投入到这道题上的总计算量(Test-Time Compute)与

可见工作记忆!如果不输出思考过程,模型只能靠单次前向传播(固定的几十层网络运算)硬猜答案;而每 多输出一个思考 Token,模型就额外跑了一次完整的全网络前向计算,且前面写下的中间步骤会进入上下文 窗口充当“外置草稿纸”,让复杂的多步推理被拆解为一系列高准确率的单步计算。(答出测试时计算量扩展 与外置草稿纸记忆得 10 分)

2. 第 2 题解析:因为人类手写的思维链样本(SFT)代表的是“人类以为什么是最好的思考步骤”,不仅标注成

本极高,而且把模型的思维死死限制在了人类既有的套路上限之内;而强化学习(GRPO)只对最终结果是 否正确进行奖惩,允许模型在庞大的策略空间中自主探索,从而涌现出比人类手写模板更细致的多路试错、 反例自检与回溯能力。(对比人类示范局限性与强化学习自主探索涌现得 10 分)
