30 SECONDS / 30 秒看懂

这一册只解决一件事：把大模型的黑盒拆成四层——分词、向量、注意力、采样。看懂后，计数、幻觉、随机性都能解释。

  • Tokenizer 把文字切成 Token ID，模型不直接看汉字/字母
  • Embedding 把 Token 放进高维语义空间，Self-Attention 再按上下文聚合
  • Temperature/Top-p 决定从概率榜单里怎么选下一个词

输入
实验 1：直接问模型“immunoelectrophoresis 里有几个字母 o，分别在第几位？”；实验 2：让模型先把每个字母编号，再统计 o。

发生了什么

直接问时，模型看到的是 Token 而不是单字母，容易数错；强制逐字母编号后，每个字母成为可见 Token，注意力能精确对齐位置。

输出

来源实验结论：强制把字符拆成带序号的 Token 后，计数准确率可到 100%。

术语拆开

Tokenizer
把文本切成 Token 并映射为编号的分词器。
Embedding
把 Token 映射成高维向量的语义坐标。
Self-Attention
让每个 Token 根据上下文计算注意力权重。

为什么有效

来源指出：模型只做“下一个 Token 的概率接龙”；不理解 Token 颗粒度，就会误判模型的计数、拼写和幻觉能力。

结构长什么样

文字 → Tokenizer → Token ID → Embedding → Self-Attention → 概率分布 → Sampler → 下一个 Token

内功01:大语言模型(LLM)底层运作原理——从分词、 高维向量到概率接⻰ 把大模型的黑盒彻底拆开:搞懂 Token 分词机制、Embedding 语义空间、Self-Attention 自注意力、温度采 样与三阶段训练全流程 核 心 知 识 参 考 : Microsoft Generative AI for Beginners 、 Maxime Labonne LLM Course 与 Modern LLM Notebook

一、顿悟时刻:哦,原来大模型在底层是这么工作的!

很多刚接触 AI 的学习者常把大语言模型(Large Language Model, LLM)想象成一个装满标准答案的数据库, 或者一个像人类一样用逻辑思考的大脑。其实,当你把 ChatGPT、Claude、Gemini 或 DeepSeek 的外壳拆 开,你会发现它的底层运行建立在三个极其优美且直观的数学机制之上。看懂这三个真相,你以后遇到任何奇 怪的 AI 现象都能一眼看穿本质。 真相一:大模型根本不认识汉字和英文字母,它眼里只有“词表编号(Token ID)” 计算机无法直接把文字放进神经网络做乘法运算。当你向模型输入一句话时,门口的第一道工序叫 Tokenizer (分词器,主流采用 BPE 字节对编码算法)。分词器手里有一本固定大小的“新华字典”(比如 OpenAI o200k_base 词表约 20 万个词元,DeepSeek-V4 / V4.1 词表与 Qwen3.8 多模态词表约 15.1 万个词元)。 它是怎么切词的? 高频词(如 apple 或 人工智能)直接对应字典里的 1 个编号(Token ID);生僻词或长单词 则会被拆成几个子词碎片(Subwords)。在现代多语言词表中,1 个英文单词平均约合 1.3 个 Token,1 个 常用汉字平均约合 0.6〜1 个 Token。 顿悟经典怪象:为什么曾经几乎所有大模型都会答错“strawberry 里有几个字母 r”? 因为在分词器眼 里,strawberry 根本不是 10 个独立字母,而是直接被换成了两个整数编号 [3412, 19845](对应 straw + berry)喂给了模型!这就像蒙住你的眼睛递给你两块拼图,让你不拆开拼图直接说出里面有几笔竖弯钩一样 困难。只有当你让模型“把每个字母用空格隔开写出来(s t r a w b e r r y)”时,每个字母才变成独立的 Token,模型立刻就能数对了! 真相二:什么是 Embedding 与 Self-Attention?“给每个词发一个高维空间坐标,再根据上下文动态 变形” 拿到一串整数编号后,模型怎么理解它们的意思?分两步走:

1. 静态语义坐标(Embedding 层):模型把每个 Token ID 映射为一串由几千个小数构成的数组(例如 4096

维向量)。你可以把它想象成一个“超级立体超市的经纬度坐标”:在这个空间里,“猫”和“小狗”的坐标 挨得极近,“苹果”和“香蕉”挨得极近。

2. 动态语境聚合(Self-Attention 自注意力机制):同一个词在不同句子里意思完全不同。比如“我去银行存

钱,看见银行门口走着一行人”——里面的“行”字到底指金融机构还是队伍?Transformer 架构的核心武 器就是自注意力机制(Query-Key-Value 矩阵运算):句子里的每一个词都会伸出“雷达触手(Query)”去 扫描句子里的所有其他词(Key),计算相关性权重。当第一个“银行”扫描到后面的“存钱”时,它的注意 力权重瞬间锁死在“存钱”上,从而把自己的向量坐标动态拉向“金融金库”区域! 真相三:大模型是怎样“吐字”的?自回归下一个词概率接⻰(Autoregressive Generation) 经过几十层自注意力网络与前馈神经网络(FFN)的计算后,模型在最后一层做的事情极其纯粹:给词表里的全 部 15 万个候选 Token 分别打一个概率分(加起来等于 100%)。比如输入“床前明月”,模型算出下一个词是 “光”的概率为 99.2%,“饼”的概率为 0.01%。选出“光”之后,模型把“床前明月光”作为新的完整输入, 重新跑一遍网络去猜第六个字“疑”——如此循环往复、每次只往前接⻰一个 Token,直到吐出代表结束的特 殊符号 <|endoftext|> 为止! 底层核心组件 一句话直觉比喻(“哦,原来是这样!”) 对日常使用 AI 的直接启示 Tokenizer(分词器) 把自然语言切成固定编号积木块的“切菜 机”。 处理字符级任务(字数精确统计、字母倒 序、密码校验)时,必须让模型先显式拆开 字符或调用 Python 工具。 Embedding(嵌入向 量) 把所有概念按意思远近摆放在高维空间里 的“语义坐标系”。 使用精准的专业术语能直接把模型的起始坐 标定位到高水平知识簇,避免滑入通俗水文 区。 Self-Attention(自注 意力) 让每个词回头看遍全文、弄清指代关系与 重点的“聚光灯矩阵”。 上下文越杂乱,注意力聚光灯越分散;用结 构化标签和清晰标题能帮模型把注意力集中 在核心指令上。 Sampler(温度与核采 样) 从候选词概率榜单里摇号抽签的“随机转 盘控制器”。 写代码、提数据选低温(T=0~0.2)只拿榜 首;写创意故事选高温(T=0.7~0.9)允许爆 冷门好词。

二、核心概念与机制深拆:大模型是怎么被训练出来的?采样参数怎么调?

1. 一颗顶级大模型诞生的三部曲(为什么基座模型只会续写,而对话模型能听懂指令?)

很多学习者分不清 Base Model(基座模型,如 DeepSeek-V4-Base / Qwen3.8-Base) 与 Instruct / Chat Model(指令/推理模型) 的区别。实际上,任何现代大模型都经历了三个截然不同的训练阶段(参考 Andrej Karpathy 的 LLM 经典拆解与 Maxime Labonne LLM Course): 第一阶段:预训练(Pre-training · 博览群书的野蛮生长)——动用数千乃至数万张 GPU,让模型在十万 亿(Trillions)Token 的互联网网页、书籍、代码库上做一件事:“遮住后一个词猜它是啥”。这一阶段耗费 了 95% 以上的算力,产出的是基座模型(Base Model)。它肚子里装满了人类知识,但它还不会回答问题 ——如果你对基座模型输入“请问感冒了怎么办?”,它会以为你在列考试卷子,顺手给你往下续写:“请问 发烧了怎么办?请问咳嗽了怎么办?” 第二阶段:监督微调(Supervised Fine-Tuning, SFT · 名师手把手教说话规矩)——为了让模型学会 “有问必答”,研究人员精心编写几万到几十万条高质量的【用戶指令 User → 理想专家回答 Assistant】对话 样本喂给模型。只用短短几天,模型就学会了遵循人类指令、按特定格式作答。 第三阶段:偏好对⻬与强化学习后训练(RLHF / DPO / GRPO · 价值观校准与深度推理进化)——通过对 比“好回答 vs 差回答”(DPO 直接偏好优化),让模型学会拒绝有害请求、减少幻觉;而在 2025‒2026 年最 前沿的推理模型(如 DeepSeek-R1、OpenAI o 系列、Claude Fable 5.1 / Opus 5.5)中,更进一步引入了 基于可验证奖励的强化学习(RLVR / GRPO)——给模型成千上万道数学与编程难题,只要最终答案算对就 给正向奖励,让模型自己摸索出多步验证、自我纠错的深度思考能力!

2. 彻底看懂两个最重要的生成控制旋钮:Temperature(温度) 与 Top-P(核采样)

无论是调用 API、配置本地模型还是使用开发者工作台,你都会看到这两个核心采样参数。它们直接决定了模型 从“概率分布榜单”里挑词的策略: 参数名称 数学作用机理(它是怎么改变概率榜单的?) 不同场景下的黄金设置值 Temperature (温度,0.0 ~

2.0)

在归一化(Softmax)前对原始得分(Logits) 做缩放:低温(趋近 0)会把第一名的优势无限 放大(让 60% 概率变成 99.9%,近乎每次都选 同一个最稳妥的词);高温(> 0.8)会把榜单削 平,让排名第 5、第 10 的冷门词也有机会被抽 中。 · 代码生成 / 数学推理 / JSON 提取:设为

0.0 ~ 0.2(追求最高确定性,零花哨)

· 通用问答 / 翻译 / 知识讲解:设为 0.3 ~

0.6

· 头脑⻛暴 / 小说故事创作:设为 0.7 ~ 1.0 Top-P (核采样,0.0 ~

1.0)

从概率最高的词开始往下累加,一旦累计概率达 到 P(例如 0.9 即 90%),就直接砍掉后面所有 低概率长尾词,绝不允许模型抽到最后 10% 那 些胡言乱语的词。 · 工业界黄金准则:通常修改 Temperature 或 Top-P 两者之一即可,不要同时大幅改动。 常规保持 Top-P = 0.9 或 0.95。

三、动手实验(Hands-on Lab):亲眼验证分词盲区与采样温度差异

请打开任意一款大模型对话界面(ChatGPT / Claude / Gemini / DeepSeek),亲手完成以下两个 3 分钟实验: 实验 1:亲手打破 Token 分词器的“字符黑盒盲区” 对照实验 A(直接提问):在不开启深度思考模式(如普通快速对话模式)下,输入:请直接回答,不要展开拼 写:单词 "immunoelectrophoresis" 中一共有几个字母 o,分别在第几个位置? 观察模型是否出现计数或位置偏 差。 对照实验 B(强制 Token 颗粒度对⻬):输入:请先把单词 "immunoelectrophoresis" 的每一个字母按 "1-i, 2- m, 3-m..." 的格式逐个编号列出,然后再统计其中字母 o 的个数与准确序号。 实验结论:当你强制模型把单个字母拆成携带序号的独立 Token 输出到上下文中时,自注意力机制就能精确 对准每一个字母位置,准确率瞬间达到 100%。 实验 2:观察不同采样策略下的概率分布坍缩 实验步骤:在支持调节参数的平台(如 OpenAI Playground、Anthropic Console、Google AI Studio 或本 地 Open WebUI)中,输入同一句未完待续的话:推开那扇尘封了三十年的木门,我看到桌子上放着一个。 对比观察:先将 Temperature 设为 0.0,连续点击生成 3 次,你会发现模型 3 次给出的续写几乎一字不差(例 如全是“落满灰尘的旧木盒”);再将 Temperature 调至 1.1,连续生成 3 次,观察模型如何跳出平庸均值,给 出截然不同的意象。

参考答案与解析

1. 第 1 题解析:有两个底层原因:1 分词器不含字数与拼音声韵母直接映射——模型看到的不是汉字笔画和拼

音字母,而是直接映射后的语义 Token ID(一个双字词可能只占 1 个 Token),导致模型在内部很难精确对 ⻬“第几个汉字”和“拼音韵母”;2 自回归单向生成不可逆——模型是从左往右逐词接⻰的,一旦前两个 词选定,后面为了凑⻬语义通顺,往往顾不上格律约束。(答出分词器编码颗粒度得 5 分,答出自回归单向 接⻰限制得 5 分)

2. 第 2 题解析:依靠 Self-Attention(自注意力机制)。当处理代词“他”时,“他”的 Query 向量会与前文

所有词的 Key 向量计算内积注意力分数;由于预训练语料中习得的因果常识(“借给某人,是因为借入方的 东西坏了”),多层注意力头会将“他”的注意力权重高比例分配给受事者“小王”,从而在深层隐藏状态中 完成指代消解。(准确答出自注意力 Query-Key 权重聚合机制得 10 分)

3. 第 3 题解析:Base 基座模型只会顺着你的输入做“文本续写”(比如把你的问题当成文章开头继续往下编问

题),而不会礼貌地回答问题。因为它只完成了第一阶段预训练(Pre-training),缺少了第二阶段 SFT(监 督指令微调,教模型学会问答对话格式) 与第三阶段 偏好对⻬/强化学习后训练(RLHF / DPO / GRPO)。 (答出只会续写不会遵循指令得 4 分,准确写出缺少的两阶段得 6 分)

4. 第 4 题解析:应将 Temperature 调低至 0.0(或 0.1)。因为 JSON 数据提取属于零容错的确定性结构化任务,

低温能使 Softmax 概率分布高度尖锐化(Greedy Decoding 贪婪解码),强制模型始终选择完全符合提示词 Schema 约束的最高概率 Token,杜绝高温度带来的随机同义词替换。(答出调至 0~0.1 得 5 分,解释尖锐 化概率分布抑制随机发散得 5 分)

5. 第 5 题解析:这源于 Transformer 推理的两个阶段差异:1 阅读输入阶段(Prefill 预填充阶段)是可以高

度并行计算的——GPU 可以同时在一个矩阵乘法里把输入的 5,000 个词全部算完;2 生成输出阶段 (Decode 解码阶段)是严格串行的自回归过程——模型必须先算出第 1 个字,才能把第 1 个字拼回去算第 2 个字,写 5,000 个 Token 就必须串行循环跑 5,000 次前向传播,受限于显存带宽(Memory-bound),因 此耗时得多!(答出 Prefill 并行与 Decode 自回归串行差异得 10 分)

6. 第 6 题解析:因为大模型的本质是基于统计分布的条件概率补全机,它内部并没有一个天然的“数据库查无

此人报错开关”。当遇到训练语料之外的陌生软件名时,自注意力机制会根据上下文里的“开源软件、命令 行参数”等词汇,激活所有常见 CLI 软件的高频参数概率分布(而在 Linux/Python 语料中,--config、-- verbose 出现频率极高),于是模型顺着最高条件概率“接⻰”出了一个看似合理实则虚构的参数名。(准确 用条件概率平滑/接⻰本能解释幻觉成因得 10 分)
