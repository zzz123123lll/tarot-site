30 SECONDS / 30 秒看懂

这一册只解决一件事：n8n 用事件触发器主动监听外部世界，用 JSON Items 数组自动逐条处理数据。

  • 触发器：Cron 定时、Webhook 外部事件、IMAP 邮件等
  • 节点默认对数组里的每个 Item 各执行一次，不写 for 循环
  • 通知前要 Aggregate 合并，否则会连响 N 次

一、顿悟时刻:哦,原来 n8n 和 Dify 的分工差异与“免写循环”机制是这么回事!

在学完《利器06:Dify 工作流》后,很多订阅者第一次看到 GitHub 上标星超过 18 万的自动化神兵 n8n 时,都会产生一个疑问:“它们俩看起来都是在画布上连节点,为什么已经有了 Dify,全世界还在疯狂用 n8n?

” 我们先用两个极其透彻的底层对比,帮你瞬间建立起自动化工程的全景坐标。

真相一:Dify 是“等你去提问的 AI 智囊团”,而 n8n 是“全天候监听外部世界并连接 400+ 款软件的神经中枢” 这两款工具的架构重心完全互补: Dify 的重心在“AI 内部推理与 RAG 知识库(被动响应)”——它需要有人在对话框提问或发来 API 请求才开始运转。

n8n 的重心在“主动事件触发(Event-Driven Triggers)与外部软件生态连接”——n8n 不需要真人守在电脑前!

它内置了成百上千种主动感应器:比如每天早上 7:00 准时通电的定时触发器(Schedule / Cron Trigger)、只要收到新邮件就触发的 IMAP 邮箱触发器、只要 GitHub/Notion/⻜书表格新增一行数据就瞬间响应的 Webhook 触发器。

一旦触发,n8n 会自动从 RSS、ArXiv 论文库或网页抓取最新数据 → 调用大模型 API(或调用你搭好的 Dify 工作流接口!)完成总结提炼 → 自动把结果写入你的 Notion 笔记库并推送到手机通知!

真相二:为什么在 n8n 里不用写 for 循环,一个节点就能自动处理 50 条数据?

揭秘“JSON 对象数组流(Items Array)” 很多新手第一次在 n8n 里连线时会感到神奇:上游的 RSS Read 节点抓到了 20 篇最新科技文章,我后面只连了 1 个 AI 总结节点,也没写任何循环语句,结果它竟然自动把 20 篇文章逐篇总结了 20 次!

当你看懂 n8n 的底层数据结构,就会直呼“哦,原来是这样!

”:在 n8n 的节点连线管道里,流动的永远是一列标准格式的 JSON 对象数组小火车:[{"json": {...}}, {"json": {...}}, ...]。

只要上游吐出了包含 N 个元素 (Items)的数组,n8n 里的绝大多数动作节点默认都遵循 “Run Once for Each Item(针对数组里的每一节车厢自动循环执行一次)” 的物理法则!

你在下游节点里写一句表达式 {{ $json.title }},它就会自动遍历每一节车厢的 title 字段。

而当你希望把 20 节车厢打包合并成 1 篇汇总日报发出去(防止连发 20 条消息刷屏)时, 只需在中间加一个 Aggregate(聚合) 节点,把 20 个 Item 合成 1 个数组即可!

n8n 核心概念底层运行机制常见新手踩坑与标准解法 Items Array 自动迭代上游输出 N 个 Item 时,下游节点默认自动循环执行 N 次。踩坑:上游抓了 10 条资讯直接连通知节点, 导致手机连响 10 次。

解法:在通知前插入 Aggregate 节点合并为 1 条。跨节点数据引用每个节点的历史输出都保存在执行上下文树中。

紧邻上一节点用 {{ $json.field }};跨越多层回头取特定节点用 {{ $('节点名称').item.json.field }}。

n8n 核心概念底层运行机制常见新手踩坑与标准解法 Webhook 测试与生产地址提供临时调试用的 /webhook-test/ 与持久监听的 /webhook/ 两套路由。

踩坑:把带 -test 的地址填进外部系统,关掉网页后报 404。解法:上线时必须换为 Production URL 并拨开右上角 Active 开关。

二、核心操作深讲:Docker 一键部署、AI Agent 节点挂载与防限流护栏

1. 2 分钟 Docker 本地持久化部署 n8n

n8n 支持通过 Docker 在本地电脑或个人服务器上免费自托管运行。

执行以下包含时区配置与数据持久化卷的命令,确保容器重启后你的工作流配置永不丢失: docker volume create n8n_data docker run -d \ --name n8n \ --restart always \ -p 5678:5678 \ --add-host=host.docker.internal:host-gateway \ -e GENERIC_TIMEZONE="Asia/Shanghai" \ -e TZ="Asia/Shanghai" \ -v n8n_data:/home/node/.n8n \ docker.n8n.io/n8nio/n8n

2. 生产级稳定性护栏:批量速率控制(Loop + Wait)与节点级自动重试(Retry On Fail)

当你用 n8n 处理成百上千条数据并调用外部大模型 API 时,最容易遇到两类故障:一是并发太快触发 API 的 429 Too Many Requests 频率限制;二是偶发网络抖动导致整条流水线中断。

请务必掌握两项防线配置: 防线一(开启节点级失败自动重试):点开任何 HTTP Request 或 AI 节点,切换到顶部的 Settings 选项卡, 开启 Retry On Fail,设置 Max Tries = 3、Wait Between Tries = 5000(毫秒),即可自动消化 95% 的偶发网络波动。

防线二(使用 Loop Over Items + Wait 控制请求节奏):当上游有 100 条数据需要逐条调用限速 API 时,插入 Loop Over Items (Split in Batches) 节点(设 Batch Size = 1),并在循环回路中串联一个 Wait(等待 2 秒) 节点,让流水线稳健匀速运转。

三、动手实验(Hands-on Lab):搭建《每日 ArXiv / 科技前沿自动追踪早报流》

实验 1:亲手完成“定时抓取 → Limit 截断 → Aggregate 聚合 → AI 综述”四步闭环

1. 在 n8n 画布中添加第 1 个节点 Schedule Trigger(设定每天早上 08:00 触发,调试时可直接点击 Test

step)。

2. 连接第 2 个节点 RSS Read,填入任意科技或学术 RSS 源(如 Hacker News https://hnrss.org/frontpage 或

ArXiv CS.AI 订阅源),点击运行你会看到输出了 20〜30 个 Item。

3. 连接第 3 个节点 Limit(设置 Max Items = 5,只保留最新 5 篇防止调试消耗过多 Token)。

4. 连接第 4 个节点 Aggregate(选择 Aggregate All Item Data Into a Single List,观察输出如何从 5 items 变成

了 1 item!)。

5. 连接第 5 个节点 AI Agent / Basic LLM Chain,挂载你的 DeepSeek / OpenAI / Ollama 模型,用 {{

JSON.stringify($json.data) }} 将 5 篇文章一次性传给模型生成结构化中文早报!
