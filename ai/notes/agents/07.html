参考答案:研发排障 Agent 的上下文工程与子智能体隔离方案

【1. 工具输出入窗过滤器(Tool Output Truncation & Summarization Hook)】

当 fetch_server_logs 工具返回原始文本 > 1,500 字符时: - 将完整原始日志保存至沙盒临时文件 /tmp/log_dump_01.txt; - 仅向主 Agent 上下文注入结构化摘要:{"log_file_ref": "/tmp/log_dump_01.txt", "total_lines": 4200, "error_summary": "共出现 37 次 OutOfMemoryError,首次发生于 03:14:02,核心堆栈位于 OrderService.java:142"}。

【2. 滑动窗口与里程碑状态压缩(State Compaction)】

每执行完 3 轮工具调用,触发一次 Compaction:将前 3 轮的完整 Tool Call / Observation 折叠为一条 100 字的【已验证排查里程碑】(如:“已排除数据库连接池满与 Redis 超时,确认问题锁定在订单导出服务的内存泄 漏”)。

【3. 子智能体上下文隔离(Sub-agent Delegation)】

当需要深入分析 50MB 的堆转储文件时,主控 Agent 派生一个独立的 LogAnalyzerSubAgent,子智能体在独立上 下文中完成数十次切片检索后销毁自身上下文,仅向主控 Agent 返回最终 200 字的根因定位结论。 得分要点拆解:设计长日志落盘引用 + 摘要入窗机制(5 分);定期折叠历史试错轮次为里程碑状态(4.5 分);利用子智能体独立上下文避免污染主控窗口(3 分)。 第 8 关
