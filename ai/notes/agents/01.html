核心原理

在 Microsoft AI Agents for Beginners 第 1‒3 课与 Agentic AI Masterclass Exercise 1 中，智能体与普通大模型调用的本质区别在于 ReAct(Reasoning + Acting)循环：模型接收用户目标后，进入“思考(Thought)→ 决定调用工具(Action)→ 获取环境反馈(Observation)→ 再次思考”的循环，直至满足终止条件。在工程实现上，无论是使用 Pydantic AI、LangGraph、CrewAI 还是 OpenAI Agents SDK（详见ed-donner/agents），都必须明确定义四个核心组件：Model（底层推理模型）、Instructions（系统级行为准则）、Tools（可执行外部函数集）与 Loop Guard（最大循环步数限制，防死循环烧钱）。

踩坑设计 vs. 工业级设计对比：

新手踩坑设计：把所有业务逻辑硬塞进一个超长 Prompt,既不限制最大迭代步数(max_steps)，也不区分状态变量，一旦外部 API 报错，Agent 就陷入无限重试死循环，几分钟耗尽 API 额度。

工业级结构化设计：显式声明智能体状态机，设置 max_iterations = 5,并严格规范每一步的 Thought /Action / Observation 输出格式。

第 1 关实操练习题：设计“电商机票差价监控与改签助手”的 ReAct 核心循环

任务背景

你需要参照 Agentic AI Masterclass 的编码范式，为一个“自动查询航班实时价格并在低于历史购票价 200 元以上时生成改签方案”的智能体编写系统指令与循环终止条件。

待改造劣质设计：“你是一个机票助手，帮我查一下用户买的航班现在多少钱，如果便宜了就帮他改签。”

通关硬性要求（满分 12.5 分）

System Instructions: Flight Rebooking Agent

你是一个严谨的机票差价监控与改签评估智能体。请严格按照以下 ReAct 循环处理用户订单，最大循环步数限制为 max_steps = 4:

每一步推理必须严格输出以下结构：

- Thought: 分析当前已知的订单原价、退改签政策与还需获取的实时数据。

- Action: 调用指定工具（如 get_Order_Info 或 fetch_Live_Flight_Price）。

- Observation: 接收工具返回的真实 JSON 数据。

业务判定与熔断规则

1. 净收益计算公式：净节省金额 = （历史出票价 - 当前实时票价） - 改签手续费。

2. 触发改签方案条件：必须同时满足 （历史出票价 - 当前实时票价） >= 200 元，且净节省金额 > 0 元。若不满足，立即进入 Final Decision 输出“暂不建议改签”及原因。

3. 异常熔断机制：若外部航班价格接口返回超时或 5xx 错误，最多允许重试 1 次（累计失败达 2 次立即终止循环），严禁盲目重复调用或编造票价，直接输出接口异常告警。

得分要点拆解

清晰定义四步 ReAct 循环与步数上限（4.5 分）；准确列出差价 ≥ 200 元且扣费后净省 > 0 的双重算式（4 分）；包含连续失败 2 次即熔断告警的防死循环机制（4 分）。
