SOURCE READING / 来源精读

Microsoft 第 8 课 Multi-Agent Design Pattern：多智能体通过角色分工、协作与交接完成单个 Agent 难以完成的任务。

逐点读懂

  1. 多智能体不是简单复制模型，而是把职责和工具切开。
  2. 智能体之间需要明确协作和交接方式。
  3. 每个角色应有独立职责边界，避免工具和权限混乱。
  4. 高风险场景需要回退/否决机制，而不是继续流水线。

核心原理

当一个智能体挂载超过 15 个工具、系统提示词超过数千字时，它的工具选错率和指令遗忘率会急剧上升。Microsoft AI Agents for Beginners 第 8 课(Multi-Agent) 与 Complete Agentic AI Engineering Course 给出的解法是“职责单一化与多智能体分治”。主流编排架构有三种：

主管路由模式(Supervisor / Orchestrator-Workers)：由一个中央主管 Agent 接收任务、拆解分发给专门的“代码专家 Agent”、“数据分析 Agent”、“合规审查 Agent”,最后由主管汇总结果。

交接接力模式(Handoffs / Swarm)：前台分诊 Agent 识别出具体诉求后，将对话控制权与精简上下文直接移交(Handoff)给对应的垂直专科 Agent。

并发聚合模式(Concurrent Aggregation)：多个不同视角的专家 Agent 同时独立评估同一份方案（如乐观派、悲观风控派、法务派），最后由聚合器合并各方意见。

第 6 关实操练习题：设计“跨境电商全自动选品与上架团队”多智能体架构

任务背景

你想用 4 个各司其职的专职 Agent 组成虚拟团队，自动完成“市场趋势挖掘 → 供应商 1688 比价利润核算 → 侵权与违禁词合规风控 → 多语种详情页生成”。

通关硬性要求（满分 12.5 分）

1. 明确定义 4 个子智能体的专属名称、唯一职责边界与各自挂载的独立工具集（严禁工具跨角色混用）（5 分）；

2. 设计各 Agent 之间传递的结构化交接数据包(State Payload / Handoff Schema)，避免把冗长的无关思考过程传给下游（4.5 分）；

3. 设计“一票否决回退机制”:若合规风控 Agent 发现外观专利侵权风险，如何直接打回选品阶段而非继续生成详情页（3 分）。

1. 四大专职 Agent 角色与独立工具集

- Agent A（趋势侦察兵 TrendScout）：仅挂载 [search_tiktok_trends, get_amazon_movers];职责：输出候选品类词。

- Agent B（供应链精算师 MarginCalculator）：仅挂载 [search_1688_suppliers, calc_fba_shipping_fee];职责：核算毛利率是否 >= 35%。

- Agent C（合规风控官 ComplianceAuditor）：仅挂载 [check_uspto_patent, scan_prohibited_keywords];职责：排查外观专利与平台违禁词。

- Agent D（多语种文案师 ListingWriter）：仅挂载 [generate_seo_listing, translate_localized_copy];职责：生成最终上架文案。

3. 主管路由一票否决机制

Supervisor 检测到 Agent C 返回的 compliance_status != "APPROVED" 时，立即阻断向 Agent D 的交接，并将 rejection_evidence 回传给 Agent A 要求排除该专利结构重新选品。
