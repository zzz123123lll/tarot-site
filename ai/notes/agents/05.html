AI AGENTS / 05

元认知与自我反思机制

为什么顶级 Agent 写出的代码或报告极少出错？

约 5 分钟·免费阅读·整理自 Microsoft AI Agents for Beginners (77.2k Stars)·直接做题 ↓

核心原理

为什么顶级 Agent 写出的代码或报告极少出错？因为它们不会把第一次生成的结果直接丢给用户！根据 Microsoft AI Agents for Beginners 第 9 课(Metacognition) 与 Agentic AI Masterclass 的 Execution Hooks 机制，元认知(Metacognition)是指让 Agent 具备“自我监控、自我评估与自我纠错”能力。核心实现模式是构建 Actor-Critic（执行者-审查者）内部循环：当 Actor 生成初稿或 SQL/Python 代码后，先由验证器（确定性单元测试 / 语法检查器 + Critic 审查提示词）按评分标准打分；只有全部指标达标才放行输出，否则将具体报错信息喂回给 Actor 进行定向修复（上限 2‒3 轮）。

第 5 关实操练习题：构建“自然语言转 SQL 报表 Agent”的自检自愈闭环

任务背景

业务人员用自然语言让 Agent 查询数据库生成月度销售报表，直接执行模型生成的 SQL 极易出现字段名拼写错误、漏加时间过滤条件或慢查询锁表。

通关硬性要求（满分 12.5 分）

1. 设计 Generator → Validator → Refiner 三步元认知工作流（4 分）；

2. 在 Validator 阶段同时设置【确定性规则检查】（如拦截 DROP/DELETE/UPDATE、强制检查是否包含 LIMIT与分区日期过滤）与【语义对齐检查】（核对是否遗漏业务口径）（5.5 分）；

3. 定义带着数据库报错堆栈(Error Traceback)回传给 Refiner 的结构化修复模板与最大重试上限（3分）。
