核心原理

在自动化工作流或批量制作资料时，我们往往需要模型严格输出 JSON、Markdown 表格或特定XML 结构，且不能带有任何“好的，这是为您生成的 JSON:”之类的前后缀。Anthropic 教程第 5 章传授了两大杀手锏：一是在指令中明确指定输出外层标签或 JSON Schema;二是预填充模型回复开头(Speaking

for the Model / Assistant Prefill)——例如在 API 中将 Assistant 的第一个字符预填为 { 或 <json>,或在对
话指令中强制要求“你的第一个字符必须是 {,最后一个字符必须是 }”。
踩坑写法 vs. 高手写法对比:
新手踩坑写法:“提取这句话里的姓名、职位和邮箱,用 JSON 格式给我:张伟目前担任星海科技产品总
监,联系邮箱是 zhangwei@xinghai.cn。”
高手强格式约束写法:
请从 <profile> 标签中提取人员信息,并严格按照下方指定的 JSON 键名输出。
输出约束:不要输出任何 Markdown 代码块符号(如 ```json)、解释说明或开场白,你的回复必须直接以左
花括号 "{" 开头,以右花括号 "}" 结尾。
指定字段:{"name": "姓名", "role": "职位", "email": "电子邮箱"}

第 5 关实操练习题：批量商品评价结构化抽取器

任务背景

你想把杂乱的用户商品评论转化为结构化数据表或 JSON,包含：情感倾向（正面/负面/中性）、提到的核心痛点词、改进建议。

待改造劣质 Prompt:“分析这条评论：吸尘器吸力很大，地毯上的猫毛吸得很干净，就是电池太不耐用了，开强档15分钟就没电了，而且充电器还很烫。帮我整理出情感、痛点和建议。”

通关硬性要求（满分 10 分）

1. 用 XML 标签包裹待分析评论（2 分）；

2. 明确定义输出 JSON 的精确键名与数据类型（如 sentiment 仅限枚举值，pain_points 为字符串数组）（4 分）；

3. 加入首尾字符强约束或 XML 输出包裹约束，确保零多余前言后缀（4 分）。
