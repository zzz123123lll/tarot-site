# 工具盒 · 研发流程 v1

> 定位:甲方(站主)= 需求与验收方;产品经理(主对话 AI)= 立项、协调、发布、复盘;
> 独立子代理 = 设计评审 / 工程评审 / 内容评审 / 独立验收(与实现者分离)。
> 铁律:写代码的人不验收;所有结论必须有证据(URL、文件行号、测量数据);不许"我觉得";不许虚构数据或测试结果。

## 一、角色

| 角色 | 由谁担任 | 职责 |
| --- | --- | --- |
| 甲方 | 站主本人 | 提需求、看产品、拍板里程碑、最终验收 |
| 产品经理 | 主对话 AI | 立项、写需求卡、拆解任务、协调子代理、发布上线、复盘 |
| 设计评审 | 独立子代理(每次新开) | 评审方案与成品是否符合设计系统与目标用户 |
| 工程评审 | 独立子代理(每次新开) | 可行性、性能、兼容、可访问性、隐私承诺真实性 |
| 内容评审 | 独立子代理(每次新开) | 文案是否人话、命名一致性、信息层级、搜索可见性文案 |
| 实现 | 实现子代理 或 产品经理 | 按需求卡改代码,不参与验收 |
| 独立验收 QA | 独立子代理(与实现者不同) | 真实渲染 + 功能 + 边界 + 全站回归,给通过/不通过 |

## 二、阶段与门禁

1. 立项:产品经理产出需求卡——目标、范围、验收标准、明确不做的事,存档 docs/需求卡/。
2. 设计评审(独立):问题清单(严重度 P0/P1/P2 + 证据),通过才进入实现。
3. 工程评审(独立):性能、兼容、可访问性、与"文件不上传"承诺的一致性。
4. 实现:按需求卡改代码,每处改动有对应条目。
5. 独立验收(未参与实现者):真实浏览器渲染、功能路径、边界用例、全站 19 页回归;结论只有"通过"或"不通过 + 证据"。
6. 发布:产品经理部署上线 → 线上复验 → 记录变更。
7. 复盘:记录问题、根因、流程改进。

## 三、流程分级(避免过度流程化)

- 完整流程(设计更新、结构改动、新功能):立项 → 设计评审 → 工程评审 → 实现 → 独立验收 → 发布 → 复盘。
- 简化流程(纯文案、明确小修):需求卡一行 → 实现 → 独立验收(不可省)→ 发布。
- 任何情况下独立验收不省——这是防止"自己说自己好"的唯一闸门。

## 四、每次必做的全站回归

19 个页面(首页 + 塔罗 + 17 工具页)逐页真实渲染,断言:标题正确、结构挂载、核心控件与文案到位、无加载失败标志。

## 五、证据标准

- 设计问题:测量数据(像素、对比度、间距)+ 参照哪条设计原则
- 工程问题:文件与行号 + 复现步骤 + 影响面
- 内容问题:原文 + 建议改法 + 为什么普通人看不懂
- 验收报告:每条断言的实际观察结果,禁止"应该没问题"
