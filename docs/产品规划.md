# 工具盒 · 产品规划 v2

> v2 修订说明:经独立审查(2026-XX)后修订。审查确认技术承诺属实,但指出:主定位弱、指标不可测、双资产骑墙、渠道真空。v2 做出三个决定:塔罗为主攻、指标改为可测的页面级会话、渠道先行备案推迟。
> 本文件是产品决策的单一事实源,每次改方向先改这里。

## 1. 诊断(与 v1 同)

18 个工具是"陈列架"不是产品:没有目标用户、没有成功标准、没有一句"为什么是你"。必须先选定定位,其余一切服从它。

## 2. 定位(已决定)

**工具盒 = 一个本地运行的工具箱 + 一副认真的塔罗牌。**

- **主攻(传播旗舰):星辉塔罗**。定位:"有依据、不套话的塔罗占卜"。确定性内核 + 高质量解读文案是唯一有差异化、有情感价值、有自传播结构的资产。
- **底座(功能层):17 个工具**。支撑卖点:"本地处理、免安装、不注册"——这是工具页的功能承诺,不是全站主口号。不再深追"隐私恐慌"叙事(经审查:该卖点窄、不可当场验证、零成本可抄)。
- **一句话对外**:首页讲工具的价值(本地、免安装、不上传);塔罗讲自己的价值(有依据、不套话);传播预算 100% 投给塔罗。

## 3. 目标用户与真问题

| 用户 | 真问题 | 对应 |
| --- | --- | --- |
| 塔罗用户(主) | 网上占卜全是套话,想要有依据、像人话的解读 | 星辉塔罗(传播主战场) |
| 办公人群 | 临时处理文件,不想装软件、不想传陌生网站 | 核心 7 工具(功能底座) |
| 学生/自媒体 | 批量压缩、格式转换、合成 PDF,免登录 | 核心 7 工具 |
| 开发者 | 顺手小工具 | 入口层 10 工具(只维护) |

## 4. 产品结构:三层

1. **特色层(塔罗,主攻)**:解读分享图(第一优先)、"有依据"品牌化。
2. **核心层(7 个,深做,桌面优先)**:图片压缩/转换/合成PDF、PDF 合并/拆分/转图/压缩。质量标准:批量、拖拽、失败不丢文件、结果即时预览、桌面端最优(移动端可用即可,不设统一门槛)。
3. **入口层(10 个,只维护)**:开发小工具,只修 bug 不加功能。

入盒规则:真实反复问题 + 浏览器内可解 + 不能被"装个 XX 就行"替代。

## 5. 渠道与预期(渠道先行)

- **第一渠道(启动即用,无需备案)**:塔罗分享图 → 朋友圈/小红书/贴吧占卜内容。图片流通不受未备案域名限制,这是唯一自增长钩子,先做。
- **第二渠道(已就绪)**:必应/Google 收录(sitemap/canonical/robots 已在位),工具长尾词 + 塔罗词。
- **备案**:推迟。若验证期被证实存在国内流量需求(如小红书回流用户抱怨打不开/百度有收录价值),再启动备案 + 国内托管。

**分阶段预期**:
- 第 1 个月 · 产品期:塔罗分享图上线 → 工具桌面端体验补齐 → 接入 Cloudflare Web Analytics(用户需在 CF 后台一键开启)。
- 第 2-3 个月 · 验证期:分享内容投放测试;观察来源结构(社交占比增长 = 分享生效)。
- 第 4-6 个月 · 判断期:按社交回流是否成立,决定塔罗是否产品化(付费解读)或转向工具内容深耕。

## 6. 指标(已改为可测)

- **北极星:周活跃会话(页面级,Cloudflare Web Analytics 可测)+ 塔罗页来源结构**。
- 本架构无后端、无 cookie,测不出用户级留存——如实承认,不设假指标。
- 塔罗产品化(若走到那一步)自带账号体系,届时再上用户级指标。

## 7. 设计原则(继承)

克制、苹果浅色、分区色系、塔罗深色特例、打开 3 秒可用、全部本地运行、人味文案。

## 8. 不做清单

- 不接大模型(塔罗产品化决策时重开此话题);
- 不做账号/云同步/社区(与"不上传"矛盾,产品化时例外);
- 不做音视频、OCR、Office 互转;
- 不无理由扩工具。
